# Rote Coding Fraktion 0.2.0

Дата: 17 ноября 2026. Обновление существующего Forge Agent, без замены движка и без создания нового приложения.

В этом документе зафиксирована первоначальная реализация 0.2.0. После неё выполнено [уточнение оформления](docs/REFINEMENT-2026-11-17.md). Приведённые ниже размеры и хеши относятся к первоначальной сборке; текущие артефакты и SHA-256 указаны в `release/SHA256SUMS.txt` и новом отчёте.

## Результат и границы проверки

Реализованы ребрендинг, задачи в Git worktrees, Agent Control, отдельный Reviewer, структурированные отчёты с ручной передачей замечаний, точки истории OpenCode, расширенный diff и сведения сессии. Сохранены Work/Chat Faction, виртуализованная лента, проекты, закрепления, модели, память, вложения, изображения, PDF и поиск.

Основные сценарии проверены настоящим OpenCode 2.3.0 и локальными HTTP/SSE-провайдерами. Локальный провайдер проверяет транспорт, сессии, политики и UI; его заданный ответ не доказывает качество анализа настоящей моделью. Отдельная попытка реального независимого review через встроенную бесплатную `opencode/deepseek-v4.1-flash-free` завершилась отказом `Free usage limit reached`. Платные модели не вызывались. Успешное содержательное ревью внешней моделью остаётся непроверенным.

Восстановление файлов из снимков не включено: доступен явно обозначенный откат истории с `files:false`, сохраняющий пользовательские файлы. После визуального уточнения меню задач поддерживает русский и английский язык; добавлены светлая тема и две тематические иконки. Подробности: [уточнение оформления](docs/REFINEMENT-2026-11-17.md).

## Git worktrees

В **Task controls → Worktrees** доступны создание отдельного дерева, выбор существующего, новая задача в выбранном дереве, отображение ветки/пути/изменений, завершение задачи с сохранением дерева и подтверждаемое удаление чистого дерева. Задачи переключаются через существующую историю. Панель Git использует директорию текущей задачи при diff, staging и операциях Git.

Создание использует `client.worktree.create`. В установленной версии параметр `branch` выбирает существующую ссылку, а созданное дерево оказывается detached. Поэтому недостающие примитивы выполняет Git CLI: `git branch -- <new> HEAD`, затем API OpenCode и `git switch -- <new>` исключительно внутри нового дерева. Основная рабочая папка не переключается. Если API завершится ошибкой, уже созданная ветка не удаляется автоматически.

Список строится по `git worktree list --porcelain -z`, чтобы видеть также деревья, созданные вне OpenCode, и их настоящие ветки. Удаление использует узкий `git worktree remove -- <directory>` без force и без удаления ветки. Перед подтверждением и непосредственно перед удалением повторно проверяются принадлежность проекту, основное/заблокированное дерево, tracked/untracked/ignored файлы и активные сессии. Рабочие папки с любыми такими файлами не удаляются. Состояние Git с ошибкой доступа/доверия показывается как ошибка, а не как отсутствие репозитория.

Привязки сохраняются в SQLite, фактическая `session.location.directory` — в OpenCode. После удаления папки история остаётся доступной в режиме чтения: операции, которым требуется исчезнувшая Location, не вызываются. Кнопки отправки и запуска в такой истории не показываются.

## Agent Control

- Каталог берётся из `client.agent.list`, без выдуманных ролей. В тестовом движке доступны Build, General, Explore, Plan, rcf-reader и rcf-reviewer.
- `rcf-reader` допускает read/glob/grep, запрещает shell, edit, делегирование, внешние инструменты и внешние директории. Чтение типовых файлов секретов также запрещено.
- Независимый агент с возможностью изменения запускается в другом worktree. Его права соответствуют Cautious. Выбор существующей общей директории для такого агента отклоняется.
- Используются настоящие `session.create({parentID, agent, model})`, `session.prompt`, `session.active`, outcome и сообщения движка. API создания ребёнка наследует директорию родителя; RCF вызывает `session.move` до prompt и проверяет фактические parentID и директорию.
- Отдельная модель действительно передаётся движку и проверена по восстановленной дочерней сессии, включая другую модель того же провайдера.
- Панель показывает задачу, агента, модель, состояние, длительность, идентификаторы, директорию, последние действия и результат. Waiting/Running/Completed/Failed/Interrupted/Unknown выводятся из состояния движка. Завершение вызова создания не считается завершением работы.
- Доступны переход к ребёнку/родителю и остановка через `session.interrupt`; информация восстанавливается после перезапуска.
- Автоматический инструмент делегирования основной задачи ограничен `rcf-reader`. Независимые пишущие агенты запускаются через Agent Control в другом дереве. Разные активные задачи RCF не могут начать запись в одну директорию. Это координация и правила движка, не OS-песочница: пользовательские программы и недоверенный plugin-код требуют отдельной границы доверия.

## Независимый Code Review

**Review changes** создаёт отдельную сессию `rcf-reviewer` с выбранной моделью и реальным catch-all `deny` для всех инструментов. Запрет повторён на уровне сессии; обычные Send, смена режима, смена проекта и одобрение дополнительного инструмента не расширяют его. Отрицательные проверки подтвердили отсутствие предложенных модели инструментов и блокировку поддельного shell-вызова.

Reviewer получает staged/working/untracked diff и diff задачи OpenCode. Системные инструкции отделяют материалы от инструкций. Типовые пути секретов исключаются, известные credentials редактируются перед передачей. Материалы ограничены 180 000 символами; частичность явно обозначается. Полный исходный контекст и фактический запуск тестов Reviewer не доступны. Это проверка предоставленных материалов, а не обещание полного аудита репозитория.

У review-сессии нет engine parentID: OpenCode автоматически возобновляет родителя после завершения ребёнка, а review не должен сам запускать исправление. Связь с исходной задачей хранится в metadata и SQLite; переходы доступны в UI.

Отчёт требует JSON со списком critical/major/minor, файлами, описанием, обоснованием, исправлением, тестами и ограничениями. Счётчики выводятся только из валидного завершённого отчёта. Невалидный ответ остаётся доступен исходным текстом с неизвестными счётчиками. Неподтверждённые строки исключаются; ошибки исполнения показываются отдельно. SHA-256 материалов выявляет устаревший отчёт.

**Fix review issues** требует актуального завершённого отчёта с замечаниями и подтверждения. Замечания отправляются основной задаче в Cautious. Повторное ревью запускается вручную; автоматического цикла нет.

## Checkpoints, diff и сведения сессии

- Checkpoints перечисляет пользовательские сообщения и доступные assistant snapshots с временем и файлами из OpenCode. Просмотр изменений подписан как diff задачи, а не точный diff выбранного снимка.
- Подтверждаемый `session.revert.stage({files:false})` + `commit` откатывает только историю начиная с выбранной точки. Не выполняются reset, checkout файлов или откат Git-коммита. При неудаче commit снимается staged-revert. Действующие задачи и непустая очередь блокируют откат.
- Восстановление содержимого файлов из снимков пока недоступно: движок не доказывает принадлежность несвязанных пользовательских правок. Возможности Git rollback и history rollback не объединены в одну кнопку.
- Git diff сохраняет полный patch, контекст и номера строк; добавлены полный diff всех файлов, группировка по папкам, переходы между файлами и открытие в Windows Notepad как внешнем текстовом редакторе. Файловые ассоциации не используются, чтобы `.cmd/.js/.exe` не запускались вместо редактирования.
- Комментарий к известной строке новой стороны diff добавляется в существующий черновик вместе с фрагментом и просьбой проверить актуальный файл. Черновик не заменяется, сообщение автоматически не отправляется. Пустые/неизвестные номера строк отклоняются в UI.
- Session details показывает фактические модель/провайдера/variant, агрегированные токены и engine-reported cost, последний input как показатель контекста, доступный размер окна, compaction, retry-шаги, ошибки и длительность. Баланс провайдера и точный остаток лимитов не выдумываются; счётчики по загруженной части истории помечаются как частичные. Нейтральное прерывание не возвращается в список ошибок, ошибки редактируются от секретов перед IPC.

## Исправления, найденные проверками

1. `worktree.create.branch` не создаёт ветку и даёт detached HEAD: добавлены недостающие Git-примитивы только в новой папке.
2. `session.create.parentID` наследует папку родителя: добавлен `session.move` и проверка до первого prompt.
3. Автоматическое возобновление родителя после ребёнка не подходит независимому review: review отделён от engine parentID.
4. Full Access confirmation мог открыться раньше запрета для Reviewer: ограничение проверяется до любых диалогов расширения прав, при этом создание новых задач не трактуется как существующая sessionID.
5. Исчезнувшая Location ломала чтение истории: добавлен режим history-only.
6. Завершение задачи повторно открывало сессию и закрывало Task controls: обновление snapshot выполняется без такого перехода.
7. Новые сведения сессии могли возвращать raw interruption в текст ошибок: используется общая классификация с Timeline и redaction перед IPC.
8. Старые UI-селекторы model picker/catalog и названий обновлены под уже существующий интерфейс; производственное поведение не упрощалось ради тестов.
9. electron-builder пытался писать кэш в недоступный AppData: сборочный wrapper задаёт workspace cache.

## Ограничения и 0.3.0

- Успешная генерация/независимое review настоящей моделью требует доступного провайдера/лимита и должна быть повторена после восстановления квоты. OAuth и живые поколения Anthropic/Ollama/LM Studio отдельно не проверены; существующие подключения не менялись.
- Reviewer намеренно не выполняет команды и не читает произвольные окружающие файлы. Следующий этап — узкий broker чтения разрешённых файлов, тестовые результаты как явные проверяемые материалы и устойчивый schema-output с поддерживаемыми моделями.
- Нужны безопасное восстановление конкретных файлов с проверкой предшествующих хешей и сохранением посторонних правок, а также diff именно выбранного checkpoint. Destructive Git reset не добавлен.
- Координация RCF предотвращает новые независимые записи в одну директорию через его действия. Она не контролирует внешние редакторы, другие приложения, произвольные программы пользователя и недоверенные plugins; это не OS-изоляция.
- Меню задач локализовано. Названия пользовательских агентов, их описания из OpenCode, ответы моделей и часть технического Git UI сохраняют исходный язык.
- Не реализованы merge задач, автоматические commits/push, удаление веток, cloud/SSH/IDE, marketplace и собственный агентный цикл.
- Исторические лимиты поиска, подготовки PDF/изображений и ручной памяти сохранены; полный FTS, OCR/DOCX и остальные исключённые направления в этот релиз не включались.
- Vite предупреждает о стартовом JS примерно 714 КБ до gzip. Нужна отдельная оптимизация ленивой загрузки панелей.
- EXE не подписаны цифровой подписью. Полный интерактивный цикл установки/удаления NSIS поверх пользовательского профиля не выполняется тестами; сохранён appId и проверена структура артефактов без установки в пользовательскую систему.

Сборка применима как проверенное локальное обновление с указанными ограничениями; она не означает, что непроверенные внешние провайдеры или файловое восстановление считаются завершёнными.
