## Нейтральное оформление

Изменены представление и CSS, сохранена существующая компоновка. Все цвета и размеры скруглений вынесены в общие токены `src/styles.css`. Основные поверхности — `#101010`, `#191919`, `#252525`; границы — `#353535`; текст — `#E8E8E8` и `#A0A0A0`. Скругления большинства элементов — 4–6 px, крупных контейнеров — 8 px. Круглыми остались небольшие статусные точки.

Настройки сохранили две колонки. Информационные карточки заменены строками и разделителями, провайдеры представлены компактными нейтральными строками. Список провайдеров больше не имеет отдельной прокрутки: прокручивается правая колонка целиком. Быстрые подключения доступны перед полным каталогом. Зелёный оставлен в небольших индикаторах успеха, статистике добавленных строк и семантической подсветке diff.

Карточка изменённых файлов использует нейтральную поверхность. Встроенный diff показывает код с номерами строк и фоном только изменённых строк. Убраны повторные заголовки, служебные строки Git и пустые отступы: карточка одного файла с одной добавленной строкой в проверке занимает **59 px**. Полный patch остаётся в отдельном просмотре. При визуальной проверке найдено и исправлено обрезание diff модальным окном внутри виртуализированной ленты. Общий компонент Modal теперь отображается через React portal в `document.body`; данные diff сохранены.

Результаты: [engine](test-results/engine-verification.json), [desktop](test-results/desktop-verification.json), [followup](test-results/desktop-followup-verification.json).

OmniRoute: [результат](test-results/omniroute-verification.json), [форма 1440](test-results/omniroute-settings-1440.png), [780](test-results/omniroute-settings-780.png). Протокол сверялся с [официальной документацией 3.8.53](https://github.com/cheaper-inference/OmniRoute/blob/release/v3.8.53/docs/reference/OPENAI_COMPATIBILITY.md). Реальный сервер пользователя и его upstream-модели не проверялись, ключи со скриншотов не извлекались и не сохранялись. Проверенный транспорт не подтверждает поддержку tools/images каждым upstream.

После сообщения пользователя о HTTP 503 выполнена дополнительная проверка публичного Endpoint без пользовательского ключа: сервер отвечал HTTP 401 на запрос без ключа и на один заведомо неверный тестовый ключ; локальный порт 20128 отклонял соединение. Это подтверждает доступность публичного адреса в момент проверки, но не устанавливает причину 503 в запросе с пользовательским ключом. Авторизованный запрос с его ключом не выполнялся.

Диагностика исправлена: 5xx больше не сопровождаются подсказкой о неправильном Base URL. Из JSON-ошибки извлекаются только ограниченные код и correlation ID; произвольное тело ответа и ключ не отображаются. 401/403, 404, 429, DNS и отказ локального подключения имеют отдельные сообщения. Заблокированный API select в пресете OmniRoute заменён подписью протокола. Unit и real-Electron проверки покрывают HTTP 503 с кодом/ID, последующую успешную загрузку и потоковый запрос. [Снимок диагностики](test-results/omniroute-503.png).

Позднее установлена отдельная причина ECONNREFUSED: повторное открытие пресета для второй модели подставляло URL по умолчанию и перезаписывало общий endpoint провайдера. Исправлено чтение сохранённых name/runtime/Base URL при открытии пресета. Каталог может использовать сохранённый активный ключ внутри Main только при точном совпадении сохранённого URL; при изменении URL требуется явно введённый ключ. Real-Electron регрессия проверяет добавление второй модели, сохранение обеих моделей и адреса, загрузку каталога с прежним ключом и защиту от передачи ключа новому URL. Текущий пользовательский config восстановлен из ошибочного localhost на публичный endpoint с предварительной проверенной копией; пользовательские генерации для проверки не запускались.

Локальный HTTP-провайдер в engine/followup — явный транспортный fixture. Большая история, 1 px PNG и 10 000 строк лога — явно помеченные импортированные QA fixtures. Они проверяют протокол, восстановление, виртуализацию и отображение; не подтверждают качество модели. В обычном приложении нет demo mode, поддельного агента или встроенной тестовой истории.

Реальная внешняя LLM проверялась отдельно от fixtures; платная модель автоматически не подставлялась. Подтверждались только операции внутри изолированного тестового проекта.

## Сборки и ограничения

Portable и NSIS формируются из production UI с включённым `opencode.exe`, лицензией движка и уведомлениями зависимостей. Итоги запуска готовых файлов и SHA-256 находятся в `test-results/` после проверок упаковки.

Итоговые Windows-сборки проверены:

- `release/win-unpacked/Forge Agent.exe`: реальная бесплатная LLM, два подтверждения, read/write/shell, настоящий diff, pin, повторный запуск, история, модель и черновик; [desktop-packaged-verification.json](test-results/desktop-packaged-verification.json).
- В готовом exe повторены проверки оформления на трёх размерах и OmniRoute transport fixture. Оба отчёта содержат `packaged: true`.
- Сам `Forge-Agent-0.1.0-x64-Portable.exe`: распаковка, запуск, OpenCode 2.3.0, настройки, нейтральный фон и штатное закрытие; [portable-verification.json](test-results/portable-verification.json).
- `app.asar` содержит актуальный UI, исключает `.runtime`, `.cache`, `test-results` и `.env`; SHA-256 включённого движка совпадает с проверенным CLI. [artifact-verification.json](test-results/artifact-verification.json), [SHA256SUMS.txt](release/SHA256SUMS.txt).

Готовые файлы: [Portable](release/Forge-Agent-0.1.0-x64-Portable.exe), [NSIS Setup](release/Forge-Agent-0.1.0-x64-Setup.exe). Установка NSIS в профиль Windows не выполнялась.

- Платные API, завершение OAuth, реальные модели Ollama/LM Studio и GitHub push/pull/PR end-to-end не проверялись: нужны соответствующие пользовательские подключения. Публикация не выполнялась.
- NSIS собран; установка в профиль Windows и удаление установщика не проверялись.
- Сборки не подписаны сертификатом издателя; Linux-пакет и автообновление не подготовлены.
- Режимы разрешений OpenCode не являются изоляцией ОС. Автономные команды работают с правами пользователя.
- Тесты надёжности не заменяют независимый security audit. Проверка junction не доказывает отсутствие всех файловых TOCTOU гонок.
- В среде автоматизации реальное окно запускалось с разрешённым доступом вне ограниченного runner: его Windows ACL мешали инициализации sandbox. В самом приложении Electron sandbox оставлен включённым и проверен во время работы.
